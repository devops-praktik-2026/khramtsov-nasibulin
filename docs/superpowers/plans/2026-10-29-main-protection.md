# Main Protection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Применить защиту main по карточке #7 и доказать три запрета практическими проверками.

**Architecture:** Дополнить существующий GitHub ruleset через REST API. Проверочные коммиты и отчёт подготовить в отдельном worktree от актуальной main; использовать один PR для красной и зелёной стадий.

**Tech Stack:** Git, GitHub CLI / REST API, GitHub Actions, Ruff, Markdown.

**Spec:** `docs/superpowers/specs/2026-10-29-main-protection-design.md` (утверждён пользователем).

## Global Constraints

- Репозиторий `devops-praktik-2026/khramtsov-nasibulin`, существующий ruleset `23659601`, имя `Защита main`.
- `enforcement: active`, цель `~DEFAULT_BRANCH`, пустой `bypass_actors`.
- Одно одобрение, squash, сброс устаревших одобрений и разрешение обсуждений сохраняются.
- Обязательны `Стиль кода`, `Тесты`, `Сборка образов`, `Поиск паролей`, `Публикация образа` от GitHub Actions `15368`; последняя штатно skipped в PR.
- Текущие незакоммиченные изменения сервисов не трогать. Слияние и одобрение остаются напарнику.

## Review Focus

- Отказ прямого push должен быть вызван защитой main, а не сетевой ошибкой или устаревшей базой: сохранить GH013 и сравнить SHA main до/после.
- Все пять проверок должны иметь точные имена и источник GitHub Actions: повторно прочитать settings.
- Красный и зелёный результаты должны относиться к соответствующим SHA одного PR: сохранить ссылки и SHA.
- При зелёном CI слияние должно блокироваться именно отсутствием одобрения: проверить reviewDecision / mergeStateStatus.
- Итоговый PR не должен содержать проверочную ошибку или чужие локальные изменения: проверить diff.

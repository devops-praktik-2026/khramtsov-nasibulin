# Контракт HTTP API сервиса заказов

Версия контракта: `1.0`

Этот документ — договорённость о внешнем поведении сервиса заказов. Базовый
адрес зависит от окружения: локально сервис доступен на `http://localhost:8002`,
а внутри `docker compose` — на имени сервиса `orders`.

## Общие правила

Все запросы и ответы с телом используют JSON и заголовок
`Content-Type: application/json`.

Карточка заказа имеет одинаковый вид во всех успешных ответах:

```json
{
  "id": 42,
  "account_id": 7,
  "item": "Кофемолка",
  "quantity": 2
}
```

Поля карточки:

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | integer | Номер заказа, присваивается сервисом и больше нуля. |
| `account_id` | integer | Номер клиента, больше нуля. |
| `item` | string | Название товара, непустая строка. |
| `quantity` | integer | Количество товара, не меньше единицы. |

Ошибки валидации используют код `422` и объект с полем `detail`. В `detail`
передаётся список проблем; каждый элемент содержит `loc` с путём к ошибочному
полю и понятное сообщение `msg`. Например:

```json
{
  "detail": [
    {
      "loc": ["body", "quantity"],
      "msg": "Количество должно быть не меньше 1"
    }
  ]
}
```

Ошибки, которые не относятся к валидации, используют объект с текстовым полем
`detail`:

```json
{
  "detail": "Заказ 42 не найден"
}
```

## Создание заказа

### `POST /orders`

Создаёт заказ для клиента.

Тело запроса:

| Поле | Тип | Обязательность | Ограничения |
| --- | --- | --- | --- |
| `account_id` | integer | обязательно | Больше нуля. |
| `item` | string | обязательно | Непустая строка. |
| `quantity` | integer | обязательно | Не меньше единицы. |

Пример запроса:

```json
{
  "account_id": 7,
  "item": "Кофемолка",
  "quantity": 2
}
```

Успешный ответ — `201 Created` и созданная карточка заказа:

```json
{
  "id": 42,
  "account_id": 7,
  "item": "Кофемолка",
  "quantity": 2
}
```

Возможные ошибки:

| Код | Когда возвращается | Тело ответа |
| --- | --- | --- |
| `404 Not Found` | Клиента с таким `account_id` не существует. | `{"detail": "Клиент 7 не найден"}` |
| `422 Unprocessable Entity` | Нет обязательного поля или нарушено ограничение поля. | Список ошибок валидации с указанием поля. |
| `503 Service Unavailable` | Сервис клиентов временно недоступен. | `{"detail": "Сервис клиентов временно недоступен"}` |

## Получение заказа по номеру

### `GET /orders/{order_id}`

Возвращает один заказ по присвоенному номеру.

Параметр пути:

| Параметр | Тип | Обязательность | Ограничения |
| --- | --- | --- | --- |
| `order_id` | integer | обязательно | Номер заказа больше нуля. |

Успешный ответ — `200 OK` и карточка заказа.

Возможные ошибки:

| Код | Когда возвращается | Тело ответа |
| --- | --- | --- |
| `404 Not Found` | Заказа с таким номером нет. | `{"detail": "Заказ 42 не найден"}` — номер в сообщении совпадает с искомым. |
| `422 Unprocessable Entity` | `order_id` не является положительным целым числом. | Список ошибок валидации с указанием `order_id`. |

## Список заказов клиента

### `GET /orders?account_id={account_id}&limit={limit}&offset={offset}`

Возвращает заказы только указанного клиента. Если заказов нет, сервис отвечает
пустым списком, а не ошибкой.

Параметры запроса:

| Параметр | Тип | Обязательность | Значение по умолчанию | Ограничения |
| --- | --- | --- | --- | --- |
| `account_id` | integer | обязательно | — | Больше нуля. |
| `limit` | integer | нет | `50` | От `1` до `200` включительно. |
| `offset` | integer | нет | `0` | Не меньше нуля. |

Успешный ответ — `200 OK` и массив карточек заказов:

```json
[
  {
    "id": 42,
    "account_id": 7,
    "item": "Кофемолка",
    "quantity": 2
  }
]
```

Если у клиента нет заказов, ответ выглядит так:

```json
[]
```

Возможная ошибка:

| Код | Когда возвращается | Тело ответа |
| --- | --- | --- |
| `422 Unprocessable Entity` | `account_id`, `limit` или `offset` не проходит проверку. | Список ошибок валидации с указанием параметра. |

## Как меняется контракт

Этот файл является источником истины для трёх запросов сервиса заказов. Любое
изменение контракта вносится только через pull request в `main`. В pull request
нужно описать причину изменения, затронутые запросы и совместимость с текущими
клиентами; прямые изменения в `main` для этого файла не используются.
